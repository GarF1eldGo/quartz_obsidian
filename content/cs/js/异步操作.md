## JS与异步操作
网页中会有很多异步任务，例如网络请求、网络图片获取、定时器计时、用户交互事件、文件操作；这些操作，都写在了JS代码中：
```JavaScript
import React, {useEffect} from 'react';

const Example = () => {
    async function getData() {
      const url = "https://example.org/products.json";
      try {
        const response = await fetch(url);
        if (!response.ok) {
          throw new Error(`Response status: ${response.status}`);
        }
        const json = await response.json();
        console.log(json);
      } catch (error) {
        console.error(error.message);
      }
    }

    useEffect(() => {
        getData();
    },[]);

    return (
        <div>hello</div>
    );
};
export default Example;
```

虽然异步任务都是写在JS代码中的，但是实际执行异步任务的，并不是JS引擎，而是浏览器。
这些异步操作，都是浏览器提供给JS的接口；JS调用接口后，浏览器在特定线程中去执行对应的任务。

浏览器提供给JS的接口，被称为[Web Api](https://developer.mozilla.org/en-US/docs/Web/API)。有些接口与异步操作有关，有些无关。一些与异步操作相关的接口：
- ﻿[Fetch](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API): 实现网络请求的接口
- ﻿[Window](https://developer.mozilla.org/en-US/docs/Web/API/Window).[SetTimeout](https://developer.mozilla.org/en-US/docs/Web/API/Window/setTimeout): 实现定时器计时
- ﻿[FileReader](https://developer.mozilla.org/en-US/docs/Web/API/FileReader): 实现异步读取文件
- ﻿[MouseEvent](https://developer.mozilla.org/en-US/docs/Web/API/MouseEvent): 鼠标事件

在浏览器的子线程中执行完异步操作后，需要与JS主线程通信，让JS主线程得到需要的内容。
> 例如setTimeout定时器计时结束，需要JS主线程调用回调函数

但是JS是单线程的，如何向运行中的线程，执行目标回调函数呢？
这需要借助任务队列实现：将待执行的回调函数，放入到任务队列中暂存起来。等待调用栈（Call Stask）变为空了，再依次执行任务队列中的函数。
任务队列有两种类型，来控制回调函数执行的优先级
- 宏任务队列（Macrotask Queue/Callback Queue/Task Queue）
- 微任务队列（Microtask Queue）

当调用栈为空时
1. 先执行微任务队列中的全部任务
2. 再执行宏任务队列中的一个任务
3. 执行微任务队列中的全部任务
4. 执行宏任务队列中的一个任务
5. 循环

哪些任务被放入到宏任务队列/微任务队列？

| 宏任务队列                                  | 微任务队列                      |
| -------------------------------------- | -------------------------- |
| setTimeout, <br>setInterval,<br>用户交互事件 | promise.then/catch/finally |
> [!info] *Nodejs环境下的事件循环*
> 在Nodejs环境中，事件循环机制不同于浏览器环境，Nodejs中使用libuv库控制事件循环，有6种队列来控制回调函数的执行。  
> 详见：[A Complete Visual Guide to Understanding the Node.js Event Loop](https://www.builder.io/blog/visual-guide-to-nodejs-event-loop)﻿

# Async/Await的作用

Async 起到的作用和new Promise类似，允许函数执行异步操作

Await 起到的作用和Promise.then类似，允许将异步操作的后续代码，作为回调函数，放入微任务队列。（异步操作出错/reject，不会被await响应）
```JavaScript
const myFunc = async () => {
    console.log("fetch start");
    await fetch();
    console.log("fetch finish");
};
```

myFunc的第一行代码，是在同步环境中执行的；下一行代码，fetch作为一个Web Api，在另一个线程中执行。
那么最后一行代码'fetch finish'，会接着在同步环境下执行吗？
不会，因为有await关键字，将fetch()后面剩余的代码内容，整体作为一个回调函数，待fetch执行结束后，放入到微任务队列中。
> 如果没有await 关键字，最后一行代码，会接着fetch()同步执行
# 用户交互事件与异步
用户交互事件例如点击、拖动，都是在另一个线程中进行识别的。该线程将用户事件，通过IPC同步给渲染主线程（Blink）
猜想：
用户事件，被放入到任务队列中；从任务队列中出来时，浏览器从window根节点开始，执行捕获、冒泡流程，并在每个节点上，执行针对该事件的，已定义回调函数。
